# Maintenance guide for agents

Read this before editing. It describes how the site is built, where content lives, and the rules that keep it consistent.

## What this is

A static personal research site for Navin Raj Prabhu (Machine Learning Researcher at ai-coustics; PhD, University of Hamburg). GitHub Pages serves the `main` branch root at https://rajprabhu.net. There is no framework, bundler or package manager.

## Files

| Path | Role | Edit by hand? |
|---|---|---|
| `scripts/build.py` | All content (publications, news, CV, links) and the HTML templates | Yes, this is the source of truth |
| `index.html`, `publications.html`, `cv.html`, `404.html`, `sitemap.xml`, `robots.txt`, `CNAME`, `assets/favicon.svg` | Generated by `build.py` | No, rebuild instead |
| `assets/style.css` | All styles and design tokens | Yes |
| `assets/main.js` | Theme toggle, publication filters, abstract toggles, figure animations | Yes |
| `assets/fonts/` | Self-hosted Source Serif 4 and Schibsted Grotesk (OFL licences included) | Rarely |
| `assets/portrait*`, `assets/phd-defence*` | Images (JPEG plus WebP) | Replace, keep names |
| `.nojekyll` | Stops GitHub Pages running Jekyll | Keep |

## Workflow

```sh
python3 scripts/build.py          # regenerate pages after any change to build.py
python3 -m http.server 8000       # preview at http://localhost:8000
git add -A
git commit -m "Short imperative summary"
git push origin main              # Pages redeploys in about a minute
```

Always commit the regenerated HTML in the same commit as the `build.py` change that produced it. Keep one logical change per commit. Commit straight to `main`; there is no CI beyond the Pages deploy.

## Common edits

- **Add a publication:** add a `dict` to `PUBS` in `build.py` (newest first). Required keys: `id` (stable, used in `publications.html#id` links), `title`, `authors` (exact name string `Navin Raj Prabhu` gets highlighted; append `*` for equal contribution and set `note`), `venue`, `detail`, `year`, `themes` (any of `recognition`, `synthesis`, `groups`), `links` (list of `(label, url)`, first one is the title link), `abstract` (or `None`). Set `selected=True` to show it on the home page (the first four selected are shown).
- **Add news:** prepend a tuple to `NEWS`: `(iso_date, display_label, html)`. Link papers with `publications.html#<id>`.
- **CV entries:** edit `EDUCATION`, `EXPERIENCE`, `TEACHING`, `INTERESTS`.
- **Job title or bio:** the intro sentence is in `index_page()`; the title also appears in `EXPERIENCE` and in the JSON-LD `jobTitle` inside `page()`. Change all three together.
- **Dissertation section:** the facts list and the two columns (Recognising affect, Synthesising affect in speech) are in `index_page()`. The overview diagram is `scene_svg()`; the column figures are `dist_svg()` (label distribution) and `conversion_svg()` (the emotion conversion pipeline).

## Design rules

- Colours come only from the CSS variables on `:root` in `style.css`. Every variable has light and dark values, defined twice for dark mode: under `@media (prefers-color-scheme: dark)` guarded by `:root:not([data-theme="light"])`, and under `:root[data-theme="dark"]`. Update both blocks when adding a variable. Check every change in both themes.
- Typography: Schibsted Grotesk for headings and UI text, Source Serif 4 for body text. Sentence case everywhere; no all-caps labels.
- One accent colour (`--accent`) for links, the dashed contribution boxes and chart highlights. Do not add more accents or gradients.
- Figures (`scene_svg()`, `dist_svg()`, `conversion_svg()`) are drawn in code as inline SVG and coloured with CSS variables so they follow the theme. Keep them inline; an `<img>` SVG cannot see the page's theme. New illustrations should match this style: thin neutral strokes, one accent colour, sans labels, no traced or clip-art imagery.
- Motion: only the figure reveals in the dissertation section, triggered once on scroll (`playOnView` in `main.js`), plus the slow arousal-slider loop in `conversion_svg()`; all wrapped in `prefers-reduced-motion: no-preference`. Do not add animations elsewhere.
- Layout must not scroll sideways at 360 px wide. Keep visible focus outlines and meaningful `alt` text.

## Rules that must not be broken

- **No third-party requests.** Fonts and images are self-hosted on purpose (GDPR; the site owner is in Germany). Do not add Google Fonts, CDNs, analytics, embeds or hotlinked images.
- **Privacy.** Never publish the phone number, home address or date of birth that appear in the CV PDFs. The public email is `lr.navin@gmail.com`. Strip metadata from new images (re-save them with Pillow) and provide JPEG plus WebP.
- **Accuracy.** Only list facts that can be verified (publication pages, DOIs, the university repository). Do not invent dates, roles, links or code repositories. Abstracts are the author's own, taken from arXiv or the publisher page.
- **Do not hand-edit generated HTML**; the next build will overwrite it.

## Before you commit

1. `python3 scripts/build.py` ran without errors.
2. Pages look right in light and dark mode, on desktop and at about 390 px wide.
3. No new external URLs in `<link>`, `<script>` or `<img>` tags.
4. `git diff` contains only the intended change.
